NW-A829 wired output: sample rates / formats - notes (2026-09-27)
Sources: src/sound/oss/icx1087-sound.c + mp200-audio.c (Sony GPL, ICX1087 = same audio driver: device
kernel strings "icx1087_audio: Starting CS42L51 codec", /proc/icx1087audio/reg03h ...), k.tgz
include/linux/soundcard.h, device kernel jp_file1_kernel.bin (base 0xC0008000) SNDCTL_DSP_SPEED/SETFMT
handler at 0xc0155348..0xc0155590.

== Hardware path
DMA (M2P LCH4) -> MP201 PCM0 (slave, left-justified, 32-bit frame per channel) -> CS42L51 (I2S MASTER,
reg04h 0x40) -> headphone amp. MCLK of the codec = SoC REFCLKO pin: SMU_REFCLKO_SEL = 0 (OSC,
CS4251_MCLK = 11.2896 MHz = 256 x 44.1k), REFCLKO_DIV 0/1/3 = /1 /2 /4.
Codec reg03h = 0x2f: single-speed mode + MCLKDIV2 ("SingleSpeedMode, MCLK/2").

== SNDCTL_DSP_SPEED (device kernel, same logic as the GPL source + one extra branch)
  if REFCLKO_SEL&7 == 0:  <=12000 -> 11025 (DIV 3); <=24000 -> 22050 (DIV 1); else 44100 (DIV 0)
  else (PLL source, icx1087_REFCLKO_change exported for BT/NC):  DIV 0x5b / 0x2d / 0x16 (/92 /46 /23),
       i.e. a ~259.66 MHz source (= 23 x 11.2896 MHz)
  48000, 88200, 96000 all come back as 44100. The codec speed mode is never touched.
SNDCTL_DSP_CHANNELS: always 2. STEREO: only 1.
SNDCTL_DSP_SETFMT / GETFMTS: caps = AFMT_S16_LE (0x10) | AFMT_S32_LE (Sony value 0x800, NOT OSS4's
  0x1000). S32 -> PCM0 data length 32 bit, no padding, DMA 32-bit mode, copy as-is (MP201_CODEC_32).
  The CS42L51 takes 24 bits in left-justified mode, so S32_LE = real 24-bit output. No AFMT_S24.
  Sony's own DSP render path uses it: the OMF core's set_pcm_int_mode does SETFMT 0x800.
Unsupported format values silently fall back to S16_LE.

== Answers
- 96 kHz / 24-bit FLAC natively: NO. 96k/48k need a 12.288/24.576 MHz MCLK family; the board clocks the
  codec from an 11.2896 MHz (44.1k family) source and the driver clamps to 44.1k. (The PLL branch, /21
  of ~259.66 MHz = 12.365 MHz, would give ~48.3 kHz, 0.6 % fast - theoretical, untested, not worth it.)
- 24-bit: YES at 44.1 kHz via SETFMT 0x800 (write 32-bit little-endian samples, top 24 bits used).
  Worth it only for volume-scaled / DSP-processed audio (headroom, no dithering); the CS42L51 DAC is
  ~98 dB class so 16 vs 24 bit is inaudible for 16-bit sources.
- 88.2 kHz: POSSIBLE IN PRINCIPLE, untested: the codec is master, so putting it in double-speed mode
  (reg03h 0x0f, via /proc/icx1087audio/reg03h, which the device kernel has) or dropping MCLKDIV2 (0x2e)
  should double LRCK to 88.2k with the same 11.2896 MHz MCLK; the PCM0 slave and the DMA just follow.
  The driver would still report 44100. ratetest -H measures it and restores 0x2f.
- DSP decoders: output rate code (param +6) only 3 = 48 kHz or 4 = 44.1 kHz; LPCMD input 8..48 kHz 16-bit.
  48 kHz output from the DSP is useless on this codec (would need ARM resampling back to 44.1k).
- Best achievable path for hi-res files: decode FLAC on the ARM (no FLAC on the DSP), then
    88.2k / 176.4k material: /2 or /4 half-band decimation to 44.1k (cheap), or 88.2k native if the
      reg03h trick works;
    96k / 192k / 48k material: polyphase resample to 44.1k (160/147 steps) on the ARM, or for 48k (and
      96k after a /2 half-band) let the DSP do it: LPCMD.FTB input code 3 (48k) -> output code 4 (44.1k),
      which also gives Sony's effects on the way;
  and play S32_LE (24-bit) at 44.1k with volume/EQ applied before truncation. 44.1k/16 content: S16.

== ratetest (effects/ratetest.c)
Prints SMU clock registers (read-only /dev/mem at 0xC8010000) and codec registers from /proc; for
44100/48000/88200/96000/32000/22050 x S16_LE/S32_LE(0x800) (+ one probe each of 0x1000 and 0x8000): shows
what SETFMT/CHANNELS/SPEED return, plays a 1 kHz tone at -20 dBFS and MEASURES the real rate
(frames consumed per second of blocking writes). -H: 88.2k experiment with reg03h 0x0f and 0x2e, S16 and
S32, measured, then restores 0x2f.
What to look for: SPEED always 44100/22050/11025, MEASURED ~44100; SETFMT 0x800 accepted; in the -H part
"MEASURED with reg03h=..." ~88200 means native 88.2k works (the tone is generated for 88.2k: it sounds
1 kHz only if the rate really doubled, 500 Hz if not). Listen for clicks / silence after the switch.
Risks: codec register writes are what the driver's own /proc interface is for; the value is restored and
AUDIO_RESTART / reboot resets it anyway. Worst case: no sound until the codec is re-initialised (reboot).
